**Technology:** HTML, CSS, JavaScript, Node.js/Express, MySQL, Electron  
**Installer choices:** Electron Builder + NSIS, or Electron Builder + Inno Setup.

## 1. Project status and safe integration

This ZIP is a target structure and starter scaffold based on the supplied screenshots. The original full source ZIP was not supplied, so some pages and backend files are placeholders or examples. This is not yet a verified production installer.

Back up the original frontend, backend and database. Copy the real source files into matching folders and merge carefully. Do not overwrite working routes, authentication, controllers, services, repositories, models, middleware, validators, SQL schema, migration history, tests, CSS or JavaScript with placeholders. No demo business records are included.

## 2. Final architecture

```text
Windows Setup.exe
  -> Electron main process
     -> starts local Node.js/Express backend
     -> waits for /api/health
     -> opens frontend in desktop window
        -> HTML/CSS/JavaScript
           -> local HTTP API
              -> routes -> middleware -> controllers
                 -> services -> repositories
                    -> local MySQL Server
                       -> persistent database directory
```

Frontend code must never connect directly to MySQL or contain database credentials. Local features can work offline; cloud APIs, remote authentication, external fonts/media and cloud backups still need internet unless replaced with offline alternatives.

## 7. Development setup commands

Install Node.js LTS and MySQL Server on the developer machine. XAMPP may be used during development if the current app already depends on it; customers must not need to start XAMPP manually.

```bat
cd path\to\Skill-Tech-Desktop-Complete-Plan
npm install
npm --prefix backend install
copy backend\.env.example backend\.env
```

Edit `backend\.env` with local development settings, create the development database and apply the reviewed real schema/migrations.

Start backend:

```bat
npm run dev:backend
```

Check health in another terminal:

```bat
curl http://127.0.0.1:4317/api/health
```

Run the desktop development workflow:

```bat
npm run dev
```

Check scaffold paths:

```bat
npm run check:structure
```

The current migration runner intentionally stops until safe versioned migrations are implemented. Do not use it to initialise a production database.

## 9. Complete Windows EXE Conversion Commands

This section explains how to convert the Skill Tech Software Solutions desktop project into a Windows installer (`.exe`) using Electron Builder and NSIS.

**Technology:** HTML, CSS, JavaScript, Node.js, Express, MySQL and Electron.

**Build environment:** Windows 10/11 with PowerShell.

### 9.1 Open the Project Folder

Open PowerShell and navigate to the project root directory.

```powershell
cd "C:\Users\kesin\Downloads\Skill-Tech-Desktop-Complete-Plan\Skill-Tech-Desktop-Complete-Plan"
```

All commands in this section must be executed from the project root unless specified otherwise.

### 9.2 Verify Node.js and npm

Check whether Node.js and npm are installed.

```powershell
node --version
npm --version
where.exe node
```

If Node.js is missing, install it from the official website:

https://nodejs.org/en/download

### 9.3 Install Project Dependencies

Install the root Electron dependencies and backend dependencies.

```powershell
npm install
npm --prefix backend install
```

Verify that the project structure is correct.

```powershell
npm run check:structure
```

Resolve any reported missing files before proceeding.

### 9.4 Prepare the Bundled Node.js Runtime

The packaged application requires a Node.js runtime if the backend is launched as a separate Node.js process.

Create the runtime directory.

```powershell
New-Item -ItemType Directory -Force ".\installer\runtime\node"
```

Find the Node.js executable installed on the development computer.

```powershell
$nodePath = (Get-Command node.exe).Source
$nodePath
```

Copy it into the project runtime directory.

```powershell
Copy-Item $nodePath ".\installer\runtime\node\node.exe" -Force
```

Verify that the file exists.

```powershell
Test-Path ".\installer\runtime\node\node.exe"
```

The expected result is:

```text
True
```

Test the copied runtime.

```powershell
& ".\installer\runtime\node\node.exe" --version
```

The command should print the Node.js version.

**Important:** Use a supported Node.js release compatible with the application's dependencies and target Windows architecture. Copying `node.exe` alone does not guarantee compatibility with every native module. Verify the runtime's redistribution terms before shipping it.

### 9.5 Verify the Backend Configuration

Before packaging, confirm that the following files exist:

```text
desktop/
  main.js
  preload.js
  lifecycle/
    backend-manager.js

backend/
  package.json
  package-lock.json
  src/
    server.js
```

Verify that:

- `desktop/main.js` starts the backend and waits for its health endpoint.
- `desktop/lifecycle/backend-manager.js` uses the correct packaged backend and Node.js paths.
- `backend/src/server.js` starts the Express server on the expected port.
- Backend dependencies are installed in `backend/node_modules`.
- The `/api/health` endpoint returns the response expected by the desktop application.
- Database settings are configured safely.
- The original frontend and backend code has been integrated without replacing working business logic with placeholders.

Test the backend and application in development mode before building the installer.

```powershell
npm run dev
```

Stop the application with `Ctrl+C` when testing is complete.

### 9.6 Build the Unpacked Windows Application

Generate an unpacked Windows build.

```powershell
npm run build:dir
```

The configured output directory is:

```text
release/
```

Inspect the generated application and confirm that the packaged resources contain the required files, including:

```text
resources/
  app.asar
  backend/
    src/
    node_modules/
    package.json
  runtime/
    node/
      node.exe
```

The exact contents depend on the Electron Builder configuration. The `extraResources` settings must copy the backend files and runtime into these locations.

If the runtime or backend files are missing, correct the packaging configuration before continuing.

### 9.7 Generate the Windows Installer EXE

After the unpacked build has been verified, run:

```powershell
npm run build:win
```

This invokes the configured Electron Builder NSIS target.

The installer is generated in the configured `release/` output directory. With the current artifact naming pattern and version `1.0.0`, the expected filename is similar to:

```text
Skill-Tech-Setup-1.0.0-x64.exe
```

The actual filename depends on the package version and target architecture.

### 9.8 Verify the Installer File

List the generated EXE files.

```powershell
Get-ChildItem ".\release" -Filter "*.exe" -Recurse |
    Select-Object FullName, Length, LastWriteTime
```

Confirm that the installer exists and has a non-zero file size.

Install the newly generated setup file and launch the application.

- The frontend opens without a blank window.
- The bundled backend starts automatically.

### 9.11 Troubleshooting

**Error: `Missing script: build:dir`**

Confirm that the root `package.json` contains:

```json
"build:dir": "electron-builder --win dir"
```

**Error: `node.exe` not found**

Check:

```powershell
Test-Path ".\installer\runtime\node\node.exe"
```

If the result is `False`, copy a compatible Node.js executable into the runtime directory and rebuild.

**Error: Backend server file not found**

Check the packaged backend path in `desktop/lifecycle/backend-manager.js` and compare it with the actual files generated under `release/`.

**Error: Backend does not become ready**

Check the backend process logs, configured port, `/api/health` response and database connection.

**Error: Database disconnected**

Verify that the MySQL Server is installed or otherwise available as intended, the database exists, credentials and permissions are correct, and reviewed migrations have been applied.

**Important:** MySQL client libraries such as `mysql2` do not install MySQL Server. The application is not fully standalone until database installation or configuration, persistent storage, migrations, backup and restore have been implemented and tested.

## 10. MySQL offline installation requirements

`mysql2` is a Node.js client; it does not install MySQL Server. Production setup must select a supported/licensed distribution and implement:
1. OS/permissions/disk preflight.
2. MySQL install or documented existing-server setup.
3. Dedicated database and least-privilege account.
4. Protected credentials outside install folder.
5. Persistent data outside install directory.
6. Service startup/readiness and port-conflict handling.
7. Versioned migrations with history.
8. Backup, restore, upgrade and rollback.
9. Uninstall that preserves customer data by default.

Never silently overwrite an existing database/server. Never embed production passwords or JWT secrets in frontend files or a packaged `.env`.

## 11. Security checklist

- Electron `contextIsolation: true`, `nodeIntegration: false`, sandbox where compatible.
- Narrow preload API; no arbitrary filesystem/shell/IPC bridge.
- Backend validation and parameterized SQL.
- Local API bound to loopback where appropriate, with protection against unauthorized local requests.
- Restrict navigation, external links, permissions and Content Security Policy.
- Keep production secrets out of packaged resources.
- Store logs in app-data and redact tokens/passwords/private records.
- Handle port conflicts; port 4317 is only a development example.
- Code-sign the installer where practical.

## 13. Troubleshooting

- **Blank window:** inspect Electron logs, page/asset paths, Content Security Policy and API readiness.
- **Backend does not start:** check packaged server path, runtime compatibility, child-process logs and port conflicts.
- **Database disconnected:** check service, host, port, database, credentials, privileges and migrations. Do not delete customer data as a quick fix.
- **Inno Setup source missing:** verify `.iss` source path and actual unpacked app directory.
- **Works only on developer PC:** test on clean Windows VM; build machines may have undeclared runtimes/settings.
- **Data missing after upgrade:** stop the app, preserve files/logs, review migration history and restore a verified backup. Never overwrite populated data without a controlled migration/backup plan.
